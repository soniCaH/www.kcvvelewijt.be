Who owns the air above the up-link chip?

Decided 2026-09-11 — Optie B, the chip owns its own air

Correction, 2026-09-19 (implementation of #2877): the "measured 2026-09-11" inventory below undercounted. Fixing the decision surfaced further routes carrying the same fault under different values it never listed — pt-10, pt-8, and pt-12 sm:pt-16 on /club/[slug], /club/contact, /club/geschiedenis, /club/word-lid, /galerij/[slug] and /ploegen/[slug]/wedstrijden. The decision itself did not change; the tables below are left as drawn on 2026-09-11 and are not a complete route inventory.

The up-link chip is the little bordered box at the top-left of every detail page that takes you back up one level — ‹ KALENDER, ‹ PLOEGEN, ‹ NIEUWS. It draws no spacing of its own. Whatever container hosts it decides how much air sits above it, and the routes never agreed on a number.

MEASURED 2026-09-11, AFTER #2876 SHIPPED
  • Four different values on the detail routes: 32px · 48px flat · 48→64px · 56→80px. (A fifth, 96→128px, is /club/ultras, a marketing hero — left out of this decision.)
  • Two routes still jump when the page finishes loading — /wedstrijd/[matchId] and /tegenstander/[clubId]. Their skeleton uses one value and the real page another.
  • The chip is the first thing you can tab to after the header on all 17 routes, so where it sits is not only decoration.

OPTIE B

The chip owns its own air

<UpLink> carries its own top margin, the same way the section-header primitive already owns the air under a heading. Any route that mounts the chip gets the right spacing for free, and a new route cannot get it wrong. The dark-band case still overrides, because there the band's padding is the spacing.

for the gap below the opening

The shared opening already owns the air below it, for exactly this reason. Its own code comment:

“The opening owns its own bottom air. Putting it here rather than at nine call sites is the whole point of the register — that gap is exactly what drifted (mb-10 / mb-8 / pb-8 / mt-10) while every route hand-rolled it.”

Optie B is the same move, one line higher up.

The one way Optie B can break the site

Double air. If the chip carries its own top margin and a route keeps its container padding, the gap becomes 96px instead of 48px. So every route has to give the value up — but five of the eight cannot simply have it deleted, because their class pads the bottom of the page as well:

Trade-offs

Optie A — container keeps it Optie B — chip owns it
Effort Edit ~17 routes + their skeletons. Mechanical. One edit in the chip, then strip the value out of ~17 routes.
Next new route Can get it wrong again — and has, on every route so far. Cannot get it wrong — spacing arrives with the chip.
Past decisions Keeps the review-round comment intact. Matches what the shared opening already does for the gap below it.
Dark-band routes Unchanged — band padding still wins. Unchanged too. The chip inside a band already carries a cream tone, so the rule is “ink tone gets top air, cream tone gets none”. No new setting.

Screenshot churn Same either way — every detail route moves, so the visual baselines all need recapturing.

Recommendation: Optie B. Optie A fixes today's four values but leaves the same trap open for route eighteen. Optie B closes it — and it is not a new idea here: the shared opening already owns the air below itself, for exactly this reason, with a code comment saying that gap “is exactly what drifted while every route hand-rolled it”.

The old review comment is not a reason to keep A. It was written about the gap below the chip, on a single route, before anyone had counted how many routes disagreed above it.

Why there were four values at all

Not years of drift — one day. All four were written by the same ticket that added the chip to 17 routes at once. At each route it dropped the chip inside whatever container that route already had, so the chip inherited that page's own padding. The numbers were never decisions about the chip.

It is also why page and skeleton disagree: a different ticket had already rewritten all 28 skeletons onto one envelope at py-8. So the chip inherited 48px on the page and 32px on the skeleton of the same route.

The dark band keeps 56px — already decided

This was open when the page was first drawn. It is not: the dark-band family's air is ruled at py-14 sm:py-20 (56 → 80px) by the page-openings decision. Keeping 56px there is following that rule, not inventing an exception, so the chip on paper takes 48px and the chip inside a band stays where it is.
