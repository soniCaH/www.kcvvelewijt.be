# Branch protection on `main`

Read this before you change `.github/workflows/` or the required checks. `.claude/CLAUDE.md` → Git Workflow step 7 points here.

`main` is branch-protected (#3133). Three required checks, all by the job's `name:` (not its id) and pinned to the GitHub Actions app: `Quality Checks + Build` (`quality-checks`), `VR — Gate` (`visual-regression-gate`, #3139) and `E2E` (`e2e`, #3151/#3220). **Never require the VR shards `Visual Regression (1/3)`…`(3/3)` by name** — when the path filter skips them, a skipped matrix job reports once as the literal `Visual Regression (${{ matrix.shard }}/3)`, so a PR that changes no story would wait forever. The gate job always reports, and it also `needs` `storybook-build`, so a broken story import blocks the merge. It is **loose**: _require branches to be up to date_ is off on wave cost, and a merge queue needs an organization-owned repository. No required reviews; admins are not enforced. **Linear history is required** — merge commits are refused on `main`; merge by squash or rebase. The _out-of-date_ banner on a pull request does not block the merge while strict is off. A docs-only pull request still merges because `ci.yml` filters docs at **job** level, and a job skipped by `if:` counts as passing — `e2e.yml` filters the same way, through its own `changes` job, never on the `on:` triggers. `e2e.yml` also dropped its `push: branches: [main]` trigger (#3151): it now runs on pull requests only, so a required `E2E` check depends entirely on that job-level filter reporting, not on a `main` run ever existing. **Never move either filter back to `on:` `paths-ignore`/`paths`** — a workflow that never triggers leaves the required check pending forever. Each later layer is _add one more required check_, never _set up protection again_. Deploy jobs never gate.
